# 0001 — 逐行注释式讲解对这个学习者失效

- 日期：2026-10-19
- 状态：已确认（来自用户直接反馈）

## 观察

用户拿到的第一份材料是 `docs/项目讲解.md`（1700+ 行，零 Java 基础版逐行注释）。
用户反馈：「之前写的文档我看不太懂」。

## 判断

不是内容不对，而是**组织顺序与工作记忆容量不匹配**：

1. 按文件顺序讲，读者在建立「这个东西整体在干嘛」之前就被灌满了字段名与方法名；
2. 没有视觉锚点，抽象概念（一致性位点、幂等、断点先后顺序）无法在脑内成形；
3. 缺少「出事了会怎样」的失败视角——而失败路径恰恰是这套系统存在的理由。

## 决定（后续所有课程默认遵循）

- 每节课**先给一张图**，图里只放「角色 + 数据流向」，不出现类名；
- 概念用生活过程承载：搬家 / 记账本 / 对清单；
- 代码只出现在「想深入时看哪里」的索引里；
- 每个机制都配一句「不这么做会出什么事故」，因为**失败视角比正确视角更容易记住**。

## 影响

第 1 课（`lessons/0001-mini-oms-panorama.md`）按上述结构重写，含 4 张静态图 + 1 个 GIF 动画。
以后新增课程继续沿用：图 → 类比 → 机制 → 失败案例 → 索引。
